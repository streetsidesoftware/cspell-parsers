# Tags

Every parser in this repo tags each segment it emits, so users can choose what gets spell checked with
`customizePlugin({ tags: { ... } })`. This page is the reference for plugin authors: how to name tags, and every
tag already in use.

## Finding the tags for a new parser

You won't know every tag up front. They emerge while you build the parser, as you find the constructs worth
telling apart.

- Start from the families below, and reuse an existing tag wherever it fits.
- Add each tag to `src/tags.ts` as soon as the parser emits it. Its `tagsAndMeaning` must list every tag the parser
  can emit, since it generates the README's tags table and the table below.
- Build segment tags with the template's `defineTag`, so a tag missing from `tagsAndMeaning` is a compile error.
- Before release, review the whole set against these conventions. After release, a renamed tag breaks users'
  filters.

## Naming conventions

- **Dot-separated, most general first:** `family.kind.variant`, as in `comment.block.doc`.
- **Emit every ancestor:** a `comment.block.doc` segment also carries `comment` and `comment.block`, and each
  ancestor is listed in `tagsAndMeaning` too, so users can filter at any level.
- **camelCase segments:** `singleQuote`, `templateLiteral`, `privateProperty`.
- **Name what the user sees, not the grammar:** `string.singleQuote`, not `char_literal`. Tree-sitter's `jsx_text`
  node becomes `jsx.text`.
- **Same syntax, same tag, across languages:** `string.singleQuote` is a rune literal in Go and a string in
  Python. Say what it means for this language in `tagsAndMeaning`.
- **Qualifiers go last:** `.doc`, `.raw`, and `.module` refine the tag before them, as in `comment.line.doc`
  and `string.singleQuote.module`.
- **A segment can carry tags from several families:** a module specifier is both `string.singleQuote.module` and
  `module.specifier.literal`, so a filter on either family finds it.
- **Mint a new family only for a new kind of text:** `jsx` for JSX text, `html` for the HTML around PHP.

The families in use:

| Family       | Covers                                                               |
| ------------ | -------------------------------------------------------------------- |
| `comment`    | Comments, by form: `line`, `block`, and `doc`                        |
| `string`     | String-like literals, by quote style or form                         |
| `identifier` | Names, by kind: `variable`, `property`, `type`, ...                  |
| `module`     | Module specifiers, whatever their quote style                        |
| `jsx`        | Text between JSX tags                                                |
| `html`       | Non-code content in a template language, such as HTML around `<?php` |
| `code`       | Everything else: keywords, punctuation, and numbers                  |

## Defaults

The `tags` export in `tags.ts` says whether each tag is checked by default.

- Tags are on by default.
- Turn off only what's noisy or not the parser's language: `code` everywhere, and `html` in PHP.
- A user can always turn a tag back on, since filters never chain.
